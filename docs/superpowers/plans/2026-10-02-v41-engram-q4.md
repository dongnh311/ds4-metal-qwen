# V4.1 Engram 4-bit (Lloyd codebook) — implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** V4.1 reads Engram tables in a new 136 B/row encoding (`lloyd4_e5m3_32_r136`), and a CPU tool converts the
341 GiB GGUF in place to it (249.04 GiB). The converted file decodes bit-identically to the scored `DS4_ENGRAM_SIM=v7`.

**Architecture:** `ds4_engram.c` owns both encodings: the table carries its encoding, `ds4_engram_read` branches on it, and
the v7 encoder lives there too. `ds4.c` accepts both encoding strings and checks the tensor width against the encoding. The
new tool `gguf-tools/deepseek41_engram_q4.c` walks the GGUF header and patches fixed-width fields. It compacts the tail
forward chunk by chunk, with a state file and a journal, and truncates at the end.

**Tech Stack:** C99 (`ds4_engram.c`, tool), C test programs with `assert`, Makefile targets, CommonCrypto SHA-256 (macOS).

**Spec:** `docs/superpowers/specs/2026-10-02-v41-engram-q4-design.md`

## Global Constraints

- Encoding strings: original `e4m3_e8m0_32_row264`; new `lloyd4_e5m3_32_r136`; in-progress marker `conversion_underway`.
  All three are 19 characters.
- New row: 136 B. Bytes 0..127 hold the codes, two per byte, with the even element in the low nibble; each nibble is
  `sign << 3 | idx`. Bytes 128..135 hold one scale per 32 values: `b = E << 3 | M`, scale = `(8 + M) / 16 · 2^(E − 16)`.
- Codebook (float): `{0.0f, 0.095f, 0.1901f, 0.2944f, 0.4126f, 0.5586f, 0.7484f, 1.0f}`.
- Encoder arithmetic is exactly the spike's v7: `up = f8_up(amax / CB[7])`, `down = f8_down(up)`. The nearest level uses
  strict `<` over k = 1..7. Error is a float sum in element order. Keep `down` only if its error is strictly smaller.
  Output is `copysignf(CB[i] * s, v)`. A zero group keeps its source zeros.
- Decode then applies the existing BF16 rounding, unchanged.
- Real file: table 1 abs offset 162 955 640 832, 384 006 168 rows. Table 2: 384 016 682 rows, new offset
  215 180 492 800 (alignment 16384). Final size 267 406 761 552 B.
- The tool uses only the CPU and the disk. It refuses to run while another process holds the file open (lsof).
- No GPU or Metal changes. `ds4_engram.o` stays built without `-ffast-math`.

## Review Focus

1. **Bit-identity of the encoder with the spike's v7.** Ties, −0, and the `up`/`down` choice. Test: an independent reference in
   `test_engram` over random rows plus crafted halfway values.
2. **Resume after an interruption at every phase.** It must give a byte-identical file. Test: `test_engram_convert` stops
   through `DS4_ENGRAM_Q4_TEST_STOP` at each phase and chunk, then resumes.
3. **Overlap of table-1 chunks with their own source.** The journal covers it. Test: tiny chunks in the fixture, so the
   journal path runs, plus a stop right after the journal is written.
4. **The loader must not accept a half-converted file, or a width that does not match.** Test: `test_deepseek41_gguf`
   fork-death cases.
5. **The pre-scan must fail on bad source data before any write.** Test: a source scale of 255 in the fixture leaves the
   file byte-identical.

### Task 2: v7 encoder

**Files:** Modify `ds4_engram.h`, `ds4_engram.c`, `tests/test_engram.c`.

**Interfaces:**
- Produces:
  ```c
  /* Encode one 264 B source row (E4M3 + E8M0) into 136 B. False (errno EDOM) on a NaN code, scale byte 255,
   * a non-finite value, or a scale candidate outside E = 0..31. */
  bool ds4_engram_encode_row136(const uint8_t src[DS4_ENGRAM_ROW_BYTES], uint8_t dst[DS4_ENGRAM_Q4_ROW_BYTES]);
  ```
- Consumes: Task 1's decode, used by the test.

- [ ] **Step 1: write the failing test `test_encoder`.**
  - Independent reference written in the test: the spike's float arithmetic, line for line.
    - `f8_up(x)`: `frexpf`, then `ceilf(m * 16) / 16`, then `ldexpf`.
    - `f8_down(s)`: `n = roundf(m * 16) - 1`; `n < 8` gives `15/16 · 2^(e-1)`, otherwise `n/16 · 2^e`.
    - Nearest level with strict `<`; float SSE in order; `eb < ea` picks down; `copysignf`.
  - **20 000 random source rows** (xorshift; codes avoid 127/255; scale bytes 117..122 as in the real data, plus some
    112..127):
    - `decode(encode(row))`, through the Task 1 read path from a temp file, must be bit-identical to
      `bf16(reference(decode264(row)))`;
    - also compare the encoded bytes against the reference's chosen (idx, sign, E, M).
  - **Crafted rows:**
    - a group whose |v|/s lands exactly halfway between two levels, so the tie goes to the lower index;
    - a group where the `up` and `down` errors are exactly equal, so `up` is kept;
    - an all-zero group with mixed ±0 source codes (0x00/0x80), which must decode with the same signs;
    - a group with amax at a mantissa of exactly 8/16, so `f8_down` takes the `n < 8` branch.
  - **Invalid sources** must be refused with `errno == EDOM`:
    - a code with `(c & 127) == 127`;
    - scale byte 255;
    - a scale making `up` > 2^15 (scale byte 127 + 23 with code 0x7e);
    - a tiny scale making `down` < 2^-16.
- [ ] **Step 2:** `make test-engram`. Expected: the link fails (`ds4_engram_encode_row136` is undefined). RED.
- [ ] **Step 3: implement `ds4_engram_encode_row136`.**
  - Same arithmetic as the reference, but kept in `ds4_engram.c`.
  - The scale encoding comes from the chosen float `s`: `frexpf` → `(m*16 - 8, e + 16)`. Check that `0 <= E <= 31`, and
    that the mantissa is an integer step (assert-like check, returns false if not).
- [ ] **Step 4:** `make test-engram`. Expected: PASS.

### Task 4: in-place converter tool

**Files:**
- Create: `gguf-tools/deepseek41_engram_q4.c`
- Create: `tests/test_engram_convert.c`
- Modify: `Makefile`. Add `gguf-tools/deepseek41_engram_q4` to the Apple build section next to the other gguf tools, and the
  target `test-engram-convert`. Both compile without `-ffast-math`.

**Interfaces:**
- CLI: `deepseek41_engram_q4 --check FILE | --sample FILE N OUT | --convert FILE | --verify FILE | --verify-sample FILE OUT`
  - Exit 0 on success, 1 on refusal or error. Every message carries the `deepseek41_engram_q4:` prefix.
  - Optional `--chunk-rows K`, default 262144; the tests use small values.
- Side files next to FILE:
  - `FILE.eq4-check`: text written by `--check`. It holds the original header fingerprint (file size, both offsets and
    row counts) and `sha256 <hex>` of the converted tail.
  - `FILE.eq4-state`: binary, written with an atomic rename. Fields: magic, version, phase (1 = blocking, 2 = compacting,
    3 = finishing), table, next_row.
  - `FILE.eq4-journal`: written with fsync. It holds the table, the chunk's first row, its row count, and the source bytes.
- Test hook: env `DS4_ENGRAM_Q4_TEST_STOP=phase:count`. `_exit(3)` right after the count-th durable step of that phase:
  - `block` — after the marker is written;
  - `journal` — after a journal write;
  - `chunk` — after a chunk's state update;
  - `header` — after the final header patch, before truncate.
- Consumes: Task 1 and Task 2 (`ds4_engram_encode_row136`, `ds4_engram_read` on the converted file for `--verify-sample`).

- [ ] **Step 1: write the failing test `tests/test_engram_convert.c`.**
  - Build a tiny V4.1-shaped GGUF the same way `test_deepseek41_gguf.c` does: v3, `general.alignment` 16384, the encoding
    KV, a small F32 tensor, then the two Engram tables last.
    - Rows: 3001 and 2999, chosen so table 1's end is unaligned.
    - Rows are random valid E4M3/E8M0 bytes.
  - Then run the tool binary through `fork`/`exec` (path from argv[1]) and check:
    1. `--check` → `--convert` → `--verify`. Exit 0 each time. File size equals `align(A + 136·N1) + 136·N2`. The header length
       is unchanged, and so is every byte before the encoding string. `ds4_engram_read` on both tables, with offsets from the
       patched header, gives exactly `decode(encode(src))`. `--verify` matches the `--check` sha.
    2. With `--chunk-rows 64` (so the table-1 journal path runs), stop at each of `block:1`, `journal:1`, `journal:2`,
       `chunk:1`, `chunk:5`, `chunk:60` (inside table 2) and `header:1`. Rerun `--convert` with no stop. The final file must be
       byte-identical to run 1's.
    3. A copy with one source scale byte set to 255: `--check` fails, `--convert` refuses (no check file), and the file is
       byte-identical to before.
    4. `--convert` on an already converted file is refused with "already converted". A non-V4.1 GGUF is refused.
    5. With the fixture held open by a child process (sleep holding an fd), `--convert` is refused.
    6. `--sample F 50 out` before conversion, then `--verify-sample F out` after it: exit 0. Flip one byte of `out`: exit 1.
- [ ] **Step 2:** `make test-engram-convert`. Expected: FAIL, because the tool source does not exist and the build fails. RED.
- [ ] **Step 3: implement the tool.**
  - **GGUF walker.** Read magic and version (3), n_tensors and n_kv. Skip KVs by type: scalars, strings, and arrays of
    scalars or strings. Record:
    - the file offset of the encoding string's bytes;
    - for each Engram tensor, the file offsets of its `dims[0]` and `offset` fields;
    - `general.alignment` and `data_start`.

    Require that the two Engram tensors have the two highest offsets and that nothing follows table 2.
  - **check:** stream table 1 then table 2 in chunks, encoding on a pthread pool over rows. Hash `t1 || zeros(pad) || t2` with
    CC_SHA256. Write the check file.
  - **sample:** xorshift with a fixed seed picks N row ids per table. Record each row's id and the BF16 decode of
    `encode(src)`. That is `decode136(encode(src))`, the same function the reader uses.
  - **convert:** state machine as in the spec's section 2.
    - Before any write, refuse if: there is no check file or its fingerprint does not match; another process holds FILE
      (`lsof -t FILE`, excluding our own pid); the state is inconsistent with the header.
    - Journal a chunk when its destination overlaps its own source range: `dst_lo < src_hi && src_lo < dst_hi`.
    - Write zeros to the padding.
    - The finish phase patches dims[0] = 136 for both tables, table 2's offset (relative to data_start) and the encoding.
      Then fsync, ftruncate and fsync. Delete the journal and state files last.
    - Resume: if the state says chunk (t, i) and a journal matches (t, i), use the journal's bytes as the source.
  - **verify:** hash file[A:] and compare it with the check file.
  - **verify-sample:** open both tables with `ds4_engram_table_open(..., LLOYD4_ROW136)` at the patched offsets, read every
    sampled id, and memcmp.
