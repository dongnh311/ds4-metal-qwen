# Ornith-1.5-122B → ds4 qwen35moe second shape (M5 Pro 64 GB) Implementation Plan

> **For agentic workers:** implement task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Run `ornith-ai/Ornith-1.5-122B` (arch `qwen35moe`, llama.cpp dialect) on the ds4 engine's existing Ornith-1.5-35B-A3B graph by adding a second shape profile (48 trunk + 1 MTP layers, n_embd 3072, 32 heads, 256 experts top-8, ff 1024, GDN v-heads 64) and loading an engine-conformed GGUF. Target machine: M5 Pro 64 GB unified, ~350 GB free disk. First file: `unsloth/Ornith-1.5-122B-GGUF` Q4_K_M (75.84 GB, mmap-streamed); second tier: an IQ2-recipe resident artifact built from it with `gguf-tools`.

**Architecture:** All qwen35moe support already exists on `develop` (a71725fb): shape-table-driven graph (`ds4_qwen35moe.inc`), type-generic MoE kernels (`qwen35_row_dot` → `qwen4_row_dot` covers Q2_K/IQ2_XXS/Q4_K/Q5_K/Q6_K/MXFP4…), args-driven attention/GDN/MTP pipelines, fp8/q4 KV modes, llama.cpp-dialect validator (`qwen35moe.*` keys) and binder (`weights_bind_qwen35moe_layer` matches the 122B tensor names exactly, including the fused output gate folded into a 2×`q_dim` `attn_q`). The 122B differs from the 35B only in dimensional fields, so the port is: second `ds4_shape` profile + shape dispatch by `qwen35moe.embedding_length` + widening the dense qtype gate with `Q6_K` (unsloth Q4_K_M embeds `output.with` Q6_K). No new kernels.

**Tech Stack:** C (ds4.c single-file engine), Objective-C (ds4_metal.m), Python 3.9+ (gguf-tools), Metal 3. Existing Makefile builds; existing real-model tests.

**Spec:** Header-verified evidence (this session):
- unsloth `Ornith-1.5-122B-UD-IQ2_XXS.gguf` header: arch `qwen35moe`, block_count 49 (48 trunk + nextn 1), embedding 3072, head 32 / kv 2 / key 256 / value 256, rope 10 MHz base, dim_count 64, experts 256 top-8 ff 1024 shared ff 1024, ssm conv 4 / state 128 / group 16 / time_step_rank 64 / inner 8192, full_attention_interval 4, context 262144.
- Tensor names per layer match `weights_bind_qwen35moe_layer` exactly: full-attn layers have `attn_q [3072, 16384]` (2×q_dim fused output gate — engine already expects this at `weights_validate_qwen35moe_layout`), `attn_k/v [*, 512]`, `attn_output`, `q_norm/k_norm [256]`; GDN layers have `attn_qkv [3072, 12288]`, `attn_gate [3072, 8192]`, `ssm_a`/`ssm_dt.bias [64]`, `ssm_conv1d [4, 12288]`, `ssm_alpha/beta [3072, 64]`, `ssm_norm [128]`, `ssm_out [8192, 3072]`; MTP block (blk.48) has `nextn.eh_proj [6144, 3072]`, `nextn.enorm/hnorm/shared_head_norm [3072]`.
- No hc_*/PLE/indexer tensors — matches the 35B contract (the qwen35 validator never asks for them).
- The ds4 GGUF type table matches llama.cpp's 2026 enum exactly (16 IQ2_XXS, 17 IQ2_XS, 18 IQ3_XXS, 19 IQ1_S, 20 IQ4_NL, 21 IQ3_S, 22 IQ2_S, 23 IQ4_XS, 29 IQ1_M, 30 BF16) — no id remap needed.

Phase 3's own IQ2-tier artifact avoids IQ1 entirely, so only (a) needs widening.

### W-D3 bugs found and fixed (all in `ds4_dflash.inc` unless noted)

1. **Stage row indexing (SIGSEGV)**: `df->stage + j*row_bytes + tp*E` mixed a
   byte offset into a float pointer; corrupts GPU tensor handles downstream
   → SIGSEGV inside memmove in `ds4_gpu_tensor_read` (~23.9 GB buffers).
   Fixed: `stage + ((j*n_taps + tp)*E)`. Was EXIT=139, now EXIT=0.
2. **Drafter model map never registered for GPU dispatch**: with
   `--dflash`, `e->mtp_ready` stays false, so at open the DFlash2 GGUF's
   mmap got no `g_model_views` — every drafter gemv failed the region wrap
   ("Metal model range 0.12..0.12 GiB is not covered") and wired=false
   silently killed the probe. Fixed in ds4.c engine open:
   `support_model_runtime_ready` now includes
   `(support_kind == DS4_SUPPORT_DFLASH && e->dflash)`.
3. **Bare `end_commands` after owned-sync gemvs returns 0** (no batch is
   open when the probe runs outside a forward) — silently unwired the
   module after the first inject pass. Fixed: `begin_commands_if_needed`
   before each inject gemv group so dispatch+commit pair up (host fc and
   k/v per layer); failure sites now print instead of disappearing.
4. **Conv dynamic-coefficient layout (the accept-0 bug)**: the reference
   reshapes conv_proj output as ggml ne `[g][k][side]` per token → flat
   `side*(K*G) + k*G + g`; my conv indexed `side*(K*G) + g*K + k`
   (g/k swapped). Symptom: drafter row0 degenerate (always one token) and
   0.0% first-accept despite a healthy pipeline. After the fix the row0
   trail tracks the trunk argmax and receipts jump to mean 3.0.
5. **Probe redraft-every-step killed the streak**: pending cycles were
   overwritten every step before the match streak could extend (receipts
   stuck at cycles=closes with hist[0] only). Fixed: draft a fresh block
   only when `!pd_valid`; a pending cycle extends across steps until
   mismatch or full-block consumption (matching the reference's one
   verify cycle per draft block).
6. Makefile `ds4.o` prerequisites now list `ds4_qwen35moe.inc
   ds4_dflash.inc` (stale-binary trap: `.inc` edits used to leave ds4.o

## 3.6d W-D4 stage 1 — DFlash2 T-row verify cycle (commit `f7b8fa7e`)

Stage 1 = **per-row-exact verify + per-row GDN snapshot sets** — the same
design the MTP deep path already validated bit-exact; stage 2 (batched
verify + GDN-input arena) is the speed lever and comes later. Decode
stays plain unless `DS4_DFLASH_VERIFY=N` (2..8) is set on a `--dflash`
session; the env is parsed in `qwen35_graph_alloc` (new `dflash` stride
arg) **before** alloc computes buffers.

**Snapshot budget (resolves the 3.6b feasibility gate, analytically):**
per GDN layer a set holds `state_n + hist_n` floats where
`state_n = v_dim × DS4_N_LIN_HEAD_DIM` = 8192×128 = **4 MiB** and
`hist_n = 3×conv_dim`; across the 36 GDN layers ≈ **155 MB per set**.
`T_v=16` ⇒ 15 sets ≈ 2.26 GB — too close to the Metal maxBuffer ceiling
next to the 37.4 GB trunk, so **stage 1 caps `T_v ≤ 8`** (7 sets ≈
1.05 GB); `T_v=4` = 3 sets ≈ 452 MB. bf16 snapshots rejected (not
bit-exact); rollback-by-replay rejected (a re-run costs c×19.6 ms). The
binary prints the exact budget at alloc: `ds4: dflash verify: rows=N
snapshot sets=N-1 (X MiB)`.

**Cycle semantics** (`ds4_session_qwen35_dflash_cycle`, next to the MTP
spec cycle): caller has sampled `first_token` from `s->logits` (anchor,
NOT yet forwarded, `g->pos` = its position). Cycle = inject pending
drafter ctx rows (`ds4_dflash_inject(g, pos−1)`) → draft a **fresh block**
of `rows−1` tokens (`ds4_dflash_draft`, no pending cache — the redraft at
the commit boundary is better informed than the probe's stale walk chain)
→ verify `toks[] = [anchor, d1..d_{rows−1}]` in ONE
`qwen35_graph_forward_tokens(..., all_rows=true)` call with
`g->verify_rows_exact` (attention/dense/GDN one row per dispatch; MoE
rows through the same row kernels the T=2/3 MTP verifies already proved
row-independent). Chain compare `argmax(rows[k]) == toks[k+1]` for
k=0..T−2; `c` = matched comparisons (0..T−1):
- commit `toks[0..c]` (`c+1` tokens); checkpoint pushes in order,
  `g->pos == checkpoint.len` invariant preserved;
- `c < T−1` ⇒ `qwen35_graph_dflash_state_swap(g, c, pos0+c+1)` —
  pointer-swap each GDN layer's live state/hist with set c — plus
  `s->logits = rows[c]`; K/V rows beyond the restored position are
  overwritten by the next forward (MTP-verified invariant), tap-ring
  re-writes are position-idempotent, and the exchanged set serves as the
  next verify's fresh snapshot dest;
- `c = T−1` (all pass) ⇒ live state already stands, `s->logits = rows[T−1]`.
The last row's argmax is **never compared** — the caller samples the
would-be bonus from `s->logits` as the next cycle's anchor, so the bonus
token commits for free. No recovery row, no dropped bonus. mtp_h carry
invariants hold for every reachable (pos0, rows) pair: after a verify the
next cycle needs k = c+1 ≤ T_v ≤ mtp_h_rows; prefill seeds chunkwise with
k == chunk rows passing `≤`.

affect only the residual and the logits, which the replay discards
(the caller continues from recurrence state alone), and K/V rows beyond
the restored position are overwritten by the next forward per the
MTP-verified invariant. The captures are consumed by the replay (conv
and prep run in place on the copies) and are refilled by every verify.
