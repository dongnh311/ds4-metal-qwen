# Sub-project 3: GSQ-RCO tensor types and the ISTA IQ3_XXS repack — ISTA runs on ds4

ds4 now loads and runs ISTA-DASLab's GSQ-RCO IQ3_XXS quantization of Qwen3.8-Flash-Next on Metal, with
Ivan's MTP layer grafted on. The Metal graph matches ds4's CPU reference within the normal GPU/CPU gap.
The three test prompts get coherent answers, and MTP accepts 77-97% of drafts. PROD's output is
byte-identical to the pre-SP3 build and its decode is within 1.3%. Speed is not done: ISTA prefills at
about 60 t/s (PROD about 600) because its experts run the per-token kernels, and it decodes at 25-27 t/s
without MTP (PROD 29-30 in the same bench). That is the spec's "correct first, fast later".

- **Verification (`verify_repack.py`):** 966 tensors copied byte-equal and 289 converted value-equal to their BF16 source, 0 mismatches. `./ds4 --cpu --inspect` exits 0 and lists every GSQ-RCO type.

`output_hc_up` was not in the plan's list of conversions. ISTA stores it in BF16. Ivan stores it in F16, and the Metal hc gate kernel reads only F16/F32/Q8_0. The first repacked file made the Metal forward fail at token 0 with no message. The fix has two parts:
- the repack converts `output_hc_up` (`2e5af5a`, test first);
- the graph gate now refuses a BF16 `output_hc_up` with a message (`ef608fa`).

Baseline binaries: `feature/nextgen-qwen` at `81d0685` (before SP3), built in `ds4-metal-data/sp3/baseline`. SP3 binaries: `feature/nextgen-sp3` at `ef608fa`. PROD model: `Qwen3.8-Flash-Next-OrcaUncensored-IQ2XXS-Q4KDownPad768-DenseQ4Kselimat-MTP.gguf`, run with PROD's flags and environment.

## Final review

A fresh Opus reviewer read the whole branch (`02fd026..ef608fa`): 0 Critical, 0 Important, 7 Minor, and all five Review Focus items pass.
- The reviewer independently checked the grid tables against `ggml-common.h`, every dequantizer and lane helper against ggml, and the alignment of the `half`/`ushort` loads.
- One Minor was re-graded to Important and fixed (`e10d1d6`): the routed-expert type predicate is shared with the DeepSeek/GLM/DSpark loaders. A file of those families with IQ3_S or Q2_0 experts would have loaded and then died at the first forward pass. The GSQ types are now accepted for Qwen3.8 only, test first.

## Open items for sub-project 5

1. **Prefill (reconciliation 3):** the tiled GEMM (`qwen4_expert_type_has_mm`) takes none of the new types. Prefill runs the per-token kernels at about 60 t/s, a tenth of PROD. A 32K prompt takes about 9 minutes. SP5 needs a tiled path, or must accept this for its candidate.
2. **SSD streaming (reconciliation 4):** the expert cache serves only IQ2_XXS gate/up with Q2_K/Q4_K down, so ISTA runs resident at about 47 GiB mapped. PROD's `--ssd-streaming` flags do nothing for it. The 256K/512K KV budget on 64 GB (wired limit 56 GiB) still has to be measured.
3. **Draft vocabulary (reconciliation 9):** `DS4_QWEN4_MTP_DRAFT_VOCAB` needs a Q8_0 output head; ISTA's is Q5_K, so that speedup is off.
4. **Decode:** 25-27 t/s without MTP, against PROD's 29-30. The one-row IQ3/IQ2 lane helpers are unoptimized: at 640 wide, IQ4_NL leaves 12 of 32 lanes idle and Q2_0 leaves 22.
5. **Uncensoring:** ISTA is censored. The refusal projection (`refusal-4-44.f32`, FFN 0.5) was measured on Ivan's weights only; its effect on ISTA is untested.
6. **Deferred minors** from the review, in the SP3 ledger:
   - error texts list old types;
   - repack manifest without source sha256;
   - no GGUF version check in `gguf_lite`;
   - Makefile CUDA test-hook deps;
   - a CUDA shared-expert type check that predates this branch.
