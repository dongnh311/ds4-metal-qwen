# ISTA hc mixer weights in F16; narrow-output dense spike

Storing ISTA's hc mixer weights (`hc_{attn,ffn}_{up,inject}`, `output_hc_up`) in F16 instead of F32
makes ISTA decode 12% faster without MTP, about 24% faster with MTP, and prefill 9% faster at 8K. The
runtime is unchanged: ISTA now takes the F16 hc kernels PROD already uses. The narrow-output dense
spike found nothing to fix; it found a different prefill cost instead (below).

GPU window 2026-10-01 22:47-23:00, gateway stack paused (hold-gateway.sh), restored backend_ok 23:02.
Branch `feature/ista-hc-f16` (`592ad403`) from develop `a82d0684`.

## The change

- The SP3 repack kept a hc tensor in F32 unless every BF16 value was exact in F16. On ISTA, 193 tensors
  (1.2 GiB) went to F32 for 29,743 of 321,781,760 values (0.009%) that lie below F16's normal range.
  Rounding them to F16 moves a value by at most 3.0e-8 (relative RMS error 2.6e-9). No value is near
  F16's limit (max |w| = 8.56).
- `tools/repack_ista_qwen4.py`: hc tensors go to F16 unless a value moves by more than 1e-6. From BF16
  only overflow or NaN can do that; those tensors keep F32.
- `tools/ista_hc_to_f16.py` rewrites the repacked GGUF by the same rule, because the ISTA source shard
  is no longer kept. It copies every other tensor and the metadata unchanged.
- New file `Qwen3.8-Flash-Next-GSQ-RCO-IQ3_XXS-DS4-MTP-hcf16.gguf`: 48,674,026,400 bytes (45.33 GiB),
  643 MB smaller than before. All 193 tensors converted.

## Narrow-output dense spike (throwaway microbench)

The bench (`bench_dense_narrow.c`, scratch, not committed) runs `ds4_gpu_qwen4_dense_mm_tensor` on ISTA's
dense shapes with random weights.

| shape | 8192 tokens TFLOP/s | 2048 tokens TFLOP/s | ms per 8K forward |
|---|---|---|---|
| attn_qkv IQ4_XS 2560→10240 (wide) | 21.92 | 21.53 | 705 |
| attn_qkv Q5_K (wide) | 19.21 | 18.96 | 805 |
| ssm_out Q5_K 6144→2560 (wide) | 18.31 | 17.26 | 507 |
| hc_down BF16 10240→320 | 20.67 | 11.98 | 249 |
| shexp gate/up IQ4_XS 2560→640 | 19.31 | 19.16 | 133 |
| shexp gate/up Q5_K | 17.41 | 16.77 | 148 |
| attn_k/v Q5_K 2560→512 | 17.44 | 14.79 | 30 |
| indexer q BF16 2560→512 | 20.07 | 17.34 | 13 |
| router F32 2560→512 (float tiles) | 4.40 | 4.34 | 234 |
| hc_up F32 320→10240 (float tiles) | 4.37 | 4.33 | 1180 |
| hc_up F16 320→10240 (float tiles) | 4.37 | 4.34 | 1179 |

- **Narrow outputs are not under-occupied.** On the tensor-op tiles they run as fast as the wide
  projections at 8K. At 2048 only `hc_down` drops (12 TFLOP/s), which costs about 45 ms of a 2.6 s
  chunk. No change.
- **New lever: hc_up and the router run on the float tiles at ~4.4 TFLOP/s.**
  - Together they cost about 1.4 s of an 8K forward. ISTA's whole 8K prefill takes 10.2 s at 802 t/s.
  - On the tensor-op tiles, F16 hc_up would cost ~0.25 s: about 0.9 s saved, roughly +9% prefill.
  - This could apply to PROD too, since PROD's hc_up is F16.
  - It changes numerics (activations as half), so PROD would need its identity/quality gate.
- The F32→F16 change does not speed up this prefill GEMM (same time); the 9% prefill gain above comes
  from elsewhere in the hc path and was not traced.
